## 🔴 Blocking

### 1. Locked chests can't be opened at all
Players couldn't open the chest, locked or not. The whole interaction is unusable, so the
exploration layer (#185) is effectively offline. Note the suggestion that it **may need a
redesign** rather than a fix — worth deciding that before patching.

### 2. Possession is broken
- Can't possess entities at all any more.
- While possessing the kobold sorcerer, neither right- nor left-clicking the Fire Charge
  produces an attack, even with the target glowing.

**Suspected regression from today (#189).** Attack moved from right-click to left-click, and
`tryPossessedAttack` moved with it — it's now called from `onPlayerLeftClick` and
`onLeftClickEntity` only. Possession *itself* is triggered by the DM-mode POSSESS tool
(`DmModeListener`, right-click), which shouldn't have been affected — so "can't possess" and
"can't attack while possessed" may be two separate faults. Investigate as two.

### 3. A crossbow killed a real player in combat
Real Minecraft projectile damage reached a player. **[CHECK BUILD]** — `e44b5d6` made the
right-click suppression unconditional for our ranged weapons precisely to stop this. If it
still happens on the new jar it's a different path (already-loaded crossbow? left-click fire?
dispenser?) and is the highest-priority combat bug: our damage must never come from Minecraft.

### 4. Crossbows/bows still fire arrows on right-click
Same root as #3. Expected behaviour: right-click does nothing for a ranged weapon; attacks go
through the left-click prompt. **[CHECK BUILD]**

## 🟠 Significant — combat flow

### 5. Reactions need a full pass
Grouped because they're one feature, not four bugs:
- Reactions aren't broadcast to the DM — a player's opportunity to react was missed entirely.
- Reactions don't use the roll system (`autoRoll` / `manualRoll` / `total`).
- Damage reactions don't appear to work at all (possibly a timeout — unclear).

Treat as one "reactions hardening" effort.

### 6. Save-spells prompt the wrong person
Frostbite prompted the **attacker** to roll. A save spell should prompt the **target** (or the
DM controlling it) to roll a CON save. Related: it showed "Apply damage (1)" instead of
prompting for `1d6` — so the damage string isn't being read either. Two faults in one spell,
and probably affects every save-spell (#182 territory).

### 7. Casting from the spellbook / arcane focus doesn't prompt
Clicking a spell in the spellbook should fill the command in chat the way every other prompt
does. Currently it doesn't. (#179 covers right-clicking a spell item; this is the menu path.)

### 8. Damage autofill produces `autoRoll autoRoll`
Duplicated keyword in the generated command. Likely the prompt appends `autoRoll` to a base
that already ends in it.

### 9. Attack/damage command flow got confused
A player ran `/combat attack meepo`, hit, then `/combat damage Yeek` — a different target.
Unclear whether it applied. The pending-damage window is keyed to the attacker's `TurnState`,
so it may have applied damage to the wrong creature, or silently no-op'd. **Worth reproducing
deliberately** — wrong-target damage is the bad outcome.

### 10. Visibility is inconsistent between attack and damage
The attack roll shows only to the player who ran the command; damage broadcasts to everyone.
Pick one rule and apply it to both. (Damage is currently `session.broadcast`, the attack prompt
is a direct `sendMessage` — the split is accidental, not designed.)

### 11. `[or let the game roll]` should fill chat, not run immediately
Same change already made for the weapon picker in `5accf30`: use `suggestCommand` so the player
confirms with Enter, rather than `runCommand` firing straight away. Apply everywhere.

### 12. Advantage/disadvantage is announced too late
Currently surfaced after the attack resolves. It should appear **when the command is being
filled in**, so the player knows before committing. Worth checking whether this is even
knowable at prompt time — it should be, since the target is known.

### 13. `/combat bonus` just consumes the bonus action
It should offer the bonus actions actually available, the way #176 describes for `/combat
action`. Fold into #176.

## 🟠 Significant — world & movement

### 14. Players kicked for flying
Two separate triggers:
- Combat started while a player was mid-jump.
- Jumping and walking to the edge of a block.

This is the vanilla anti-fly kick reacting to our movement handling (heavy slowness, turn
locks). Needs either `allow-flight=true` on the server plus our own guard, or suppressing the
kick while a combat session is active. It **will** happen again — jumping is not exotic.

### 15. Players use boats to move outside their turn
Movement restriction doesn't cover vehicles. A player in a boat bypasses turn order entirely.

## 🟡 Polish & content

### 16. Character deletion leaves items behind
`/character delete` removes the YAML (`CharacterPersistenceLoader.removeCharacter`) and nothing
else. The character sheet paper, weapons, armor and ammo stay in the player's inventory as
orphaned items pointing at a character that no longer exists.
**Decide:** strip all items tagged to that character on delete, or leave them as loot? Stripping
is tidier; leaving them is kinder if someone deletes by accident.

### 17. Killing a player drops their character creation sheet
Player-vs-player killing drops the "Create Character" paper as an item. Probably not worth
fixing — as noted, players won't normally do this — but the general fix (keep plugin items on
death, or make them undroppable) would also cover the sheet being dropped or lost accidentally,
which *is* plausible.

### 18. Artificer lacks enough 1st-level spells
A max-spells artificer runs out of options. The spell list needs filling out.

### 19. Kobold sorcerer carries an arcane focus
`kobolds.yml` gives it `arcane_focus` in inventory. Probably unintended — its Fire Bolt is a
stat-block attack, not a cast spell, so the focus does nothing. Likely just loot noise.

### 20. DM mode wants a spawn tool
Spawning entities is command-only (`/dm entity spawn`). A DM-mode tool would match the rest of
the toolkit (#187 covers DM-mode tooling and submenus).

## ❔ Not our bug (probably)

### 21. `Unknown registry key ... minecraft:iron_chain -> using default`
```
[18:27:13 ERROR]: Recoverable errors when loading section [0, -1, -31]:
(Unknown registry key in ResourceKey[minecraft:root / minecraft:block]: minecraft:iron_chain -> using default)
```
This is **Minecraft's own chunk loader**, not the plugin — nothing in our code places or names
blocks. `minecraft:iron_chain` is not a block id in 1.21.8 (vanilla is `minecraft:chain`), so
the world contains a block written by a **different version** — most likely the world was opened
at some point in a newer client/server where chain variants were renamed or added.

It says *Recoverable* and substitutes a default block, so it's cosmetic: one block somewhere in
that chunk will render as the wrong thing. Worth checking whether the world has ever been loaded
in a newer Minecraft version. Unrelated to the player swinging at things — that just loaded the
chunk.
